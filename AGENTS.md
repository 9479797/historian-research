# Инструкции для работы с historian-research

Этот репозиторий содержит два отдельных навыка для исторического исследования. Он не является автоматическим агентом и не содержит пользовательские архивы.

## Маршрутизация

- Вопросы о **достоверности факта, дате, происхождении документа, независимости свидетельств** → `skills/historian/SKILL.md`.
- Вопросы о **причинах событий, сравнении исторических кризисов и оценке объяснений** → `skills/historian-analyst/SKILL.md`.
- При комплексном исследовании сначала установить источниковую базу через Historian, затем анализировать причинные связи с помощью Historian Analyst.
- Фокус: история России XIX — начала XX века. Не расширять исследование на несвязанные эпохи без запроса.

## Обязательный анализ скрытых предпосылок

При всяком сложном историческом исследовании применять [методику чтения «между строк»](docs/CONTEXTUAL_READING_METHOD.md), включая социальный статус, материальное положение, интересы, умолчания и возможные косвенные свидетельства. Не останавливаться на проверке буквального высказывания; отдельно выводить скрытую шкалу сравнения и альтернативные объяснения. Для важных версий показывать следы, которые могли бы их подтвердить **или опровергнуть**.

Для исследования лекции о финансировании революции читать [реестр исходников Claude](docs/CLAUDE_LECTURE_SOURCES_2026-11-24.md): две транскрипции, книга Спенса, Word-разбор и две редакции источников сохранены в частной Библиотеке ChatGPT. **Не публиковать полные тексты чужой лекции и книги в публичном GitHub без проверки прав.** Не путать транскрипцию с аутентичной аудио/видеозаписью, а критику лектора — с его собственными словами.

## Работа из ChatGPT

1. Открыть нужный `SKILL.md` в текущей версии GitHub и относящиеся к задаче справочные файлы. Сама доступность GitHub-коннектора **не означает автоматическую активацию навыка** в каждом чате.
2. Если документ или исторический источник хранится только на Mac, запросить или использовать доступную в текущем разговоре копию; нельзя считать, что GitHub предоставляет доступ к локальным файлам.
3. Сначала устанавливать проверяемые факты и их происхождение, затем формулировать гипотезы, альтернативные объяснения и пределы уверенности. Отделять прямые свидетельства от поздних воспоминаний, интерпретаций и выводов.
4. Не подменять неизвестные сведения выдуманными ссылками, авторством, страницами, цитатами или архивными шифрами. Для значимых спорных утверждений проверять первоисточники и независимость свидетельств.
5. Фиксировать итог работы в согласованном с пользователем месте. Исследовательские документы и личные материалы не публиковать в этом открытом репозитории без отдельного указания.

## Состав и обновление методик

- `skills/historian/SKILL.md` — основная инструкция по исторической критике источников.
- `skills/historian-analyst/SKILL.md` — краткая рабочая инструкция; подробности в `references/full-methodology.md` внутри этого навыка.
- `optional-methods/` — исходные файлы трёх дополнительных методик. Их **копии** размещены внутри `skills/historian/references/optional-methods/` и `skills/historian-analyst/references/optional-methods/`. При обновлении одной методики поддерживать идентичность всех трёх версий.
- `README.md` фиксирует происхождение навыков и ссылки для ручной проверки обновлений их оригиналов. Не заменять адаптированные версии содержимым upstream автоматически: сначала сравнивать и отдельно принимать подходящие изменения.
- Не восстанавливать ранее удалённые американские примеры и узкоспециальные процедуры, если они не нужны для целевой тематики.

## Уведомления и локальные обновления

- Новые изменения **исходных** Historian и Historian Analyst проверяются еженедельно через `.github/workflows/check-upstreams.yml` по соответствующим папкам оригинальных репозиториев. Новые версии не внедряются автоматически: создаётся GitHub Issue с назначением владельцу `9479797`.
- При дальнейшем изменении исходной версии сравнивать содержимое соответствующих навыков, не перезаписывать адаптации и три дополнительные методики. Устранить несоответствие копий `optional-methods/` перед завершением правки.
- На Mac синхронизация **двух личных GitHub-репозиториев** выполняется скриптом `scripts/sync-macos.sh`, если пользователь самостоятельно установил `scripts/install-macos-sync.sh`. Синхронизатор использует только `git fetch` и `git merge --ff-only` при чистой ветке `main`. Не обновлять сторонние upstream непосредственно на Mac.
- При появлении новой версии upstream, требующей обновления, прежде проверить изменения и приватностные настройки, затем принять их в свой GitHub. Только после этого локальная синхронизация получает обновление.
- Еженедельные проверки в публичных репозиториях GitHub могут быть отключены после длительного бездействия; проверять раздел Actions. GitHub Issues/уведомления аккаунта должны быть включены для фактической доставки сигналов.

## Перед коммитом

1. Сравнить изменения с действующими инструкциями.
2. Проверить ссылки на справочники, не допустить ошибок путей.
3. При изменении `optional-methods/` сверить контрольные суммы двух вложенных копий.
4. Сохранить принцип: понятная основная инструкция, подробные методики по запросу, минимум лишнего контекста.
5. Описать, какие файлы и почему изменены, а что осталось непроверенным.

**Примечание:** локальная установка репозитория на Mac нужна только для самостоятельного запуска или использования этих навыков в локальной среде; для чтения и редактирования через подключённый GitHub она не обязательна.

## Проверка исторических текстов и версий

- Использовать [протокол QA](docs/RESEARCH_QA_PROTOCOL.md) при редактировании исследовательских материалов: к каждому существенному утверждению — конкретное место источника, статус проверки и независимая сверка для спорных выводов.
- Не считать гипотезу доказанной лишь по возможной выгоде; финансирование, согласование, намерение и причинное влияние требуют отдельного подтверждения.
- Не выдавать сведения из аннотации, библиографии, рецензии или результатов поиска за проверенные цитаты из полного текста книги.
- Зафиксировать дату и модель пересчёта исторических денег; не смешивать золотое содержание, курс и покупательную способность.
- Язык или страна публикации сами по себе не являются доказательством недостоверности. Проверять заинтересованность, независимость и происхождение источника предметно, сохраняя пользовательские пометки происхождения в исходных реестрах.
- Исследовательская ветка `research/zhurnal-2026-11-14` содержит незавершённые материалы. **Не объединять автоматически с main.** Сначала сверять источники, делать редлайн и получать согласование.
- Для изменения необязательной методики обновить все три физические копии и выполнить `python scripts/validate_optional_methods.py` и `python -m unittest discover -s tests`. Проверка проводится также через GitHub Actions; сообщение о создании workflow само по себе не подтверждает успешный запуск.
